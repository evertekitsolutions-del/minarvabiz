# Repository Licensing & Compliance

## Repository status

Minarva Biz is a **proprietary commercial product** owned by Evertek IT
Solutions. The repository is not open source. The root `package.json` is
intentionally marked `"private": true` and `"license": "UNLICENSED"`.

The authoritative repository notice is the root `LICENSE` file. Repository
access, including access to a public Git hosting location, does not by itself
grant rights to copy, redistribute, sublicense, sell, or deploy the proprietary
Minarva Biz source or binaries.

## Product license vs source-code rights

Minarva Biz has two separate licensing concepts:

- **Product entitlement / activation** — the Ed25519 license-token system
  controls customer plan, edition, features, expiry, activations, and devices.
- **Repository/source rights** — governed by the root `LICENSE` and any
  separate written agreement with Evertek IT Solutions.

A valid activation token is therefore evidence of a product entitlement; it is
not a source-code license and does not grant redistribution or modification
rights.

## Third-party software

Third-party software is excluded from the proprietary claim and remains under
its own license. The repository enforces this through:

- `security/dependency-license-policy.json`;
- `scripts/dependency-license-policy.mjs`;
- the CycloneDX SBOM generated by the SBOM workflow;
- the machine-readable dependency-license inventory;
- `THIRD_PARTY_NOTICES.md`.

Permissive dependencies can pass the automated allowlist. Denied licenses fail
the build. Copyleft/review-required licenses must have an explicit package
review and rationale. Unknown licenses fail closed.

## Release compliance checklist

A commercial release is compliance-ready only when all of the following are
true:

- the commit has passed CI, SAST, dependency security, secret scanning, SBOM,
  and dependency-license gates;
- the SBOM and dependency-license inventory are archived with the release;
- all third-party components actually shipped in the target artifact have their
  required copyright/license notices preserved;
- any reviewed copyleft component has its distribution obligations handled for
  the exact packaging method and target platform;
- proprietary Minarva Biz materials are distributed only under an authorized
  customer/reseller/partner agreement;
- no private signing keys, service-role credentials, or license-issuer secrets
  are included in client artifacts;
- customer-facing terms do not claim ownership of third-party components or
  override rights that their licenses require.

## Change control

A dependency update that introduces a new license classification must not be
released until the dependency-license policy passes. A change to ownership,
commercial distribution terms, or source-code rights must update `LICENSE`,
this document, and the README license section in the same pull request.

This document is an engineering compliance declaration for the repository and
release process. Contract-specific commercial terms should remain in the
applicable signed customer, reseller, employment, contractor, or partner
agreement.
